== Overview
This repository contains a Python Playwright Pytest automation framework for the OpenCart demo application.

The framework is intentionally separated into two major layers:

. *Deterministic Framework Layer* — the real automation execution framework that runs tests through Pytest, Playwright, Allure, and optional TestRail integration.
. *AI Assist Layer* — an optional agentic layer that uses Playwright Codegen recordings and prompt-based planner/generator agents to create test plans and implementation recommendations.

The most important design principle is:

[IMPORTANT]
====
The AI layer does not run inside the normal test execution path.

Jenkins / Pytest execution remains deterministic. AI is used only to assist with recording, planning, code recommendation, and future maintenance.
====

== Technology Stack

[cols="1,2", options="header"]
|===
| Technology | Purpose

| Python
| Main programming language for the automation framework.

| Pytest
| Test runner, fixture engine, marker support, and reporting hook integration.

| Playwright Python Sync API
| Browser automation engine used by the deterministic test framework.

| pytest-playwright
| Provides Playwright fixtures and Pytest command-line options such as `--browser` and `--headed`.

| Allure Pytest
| Produces raw Allure results and supports test steps, screenshots, features, stories, and severity metadata.

| Allure Commandline
| Converts `reports/allure-results/` into generated HTML reports under `reports/allure-reports/`.

| TestRail API
| Optional publishing of Pytest results to TestRail using `@pytest.mark.testrail(case_id="...")`.

| Playwright Codegen
| Used by the AI assist layer to record real user flows.

| Agent Prompts
| Planner and generator prompt files used to convert recordings into test plans and code recommendations.
|===

== Deterministic Framework Layer

The deterministic layer is the real automation framework. It is responsible for test execution, browser management, page actions, business scenarios, assertions, reporting, and TestRail publishing.

It follows this execution model:

[source,text]
----
Pytest Test
  ↓
Scenario Layer
  ↓
DAO Layer
  ↓
ActionAgent
  ↓
Page Object Locators
  ↓
Playwright Page
  ↓
Application Under Test
----

=== Deterministic Layer Responsibilities

[cols="1,2", options="header"]
|===
| Area | Responsibility

| `conftest.py`
| Pytest control center. Defines command-line options, Pytest hooks, browser fixtures, page fixtures, `RuntimeAgent`, Allure lifecycle, and TestRail publishing lifecycle.

| `config/`
| Environment configuration for QA, UAT, and PROD plus global framework settings.

| `coreAgents/`
| Core reusable agents such as `ConfigAgent`, `PathAgent`, `LoggerAgent`, `RuntimeAgent`, `ActionAgent`, `AllureAgent`, and `TestRailAgent`.

| `pageObjectLocators/`
| Locator classes only. Each class stores Playwright locator objects for a page or component.

| `dao/`
| Page-level action layer. DAO classes extend `ActionAgent` and perform actions such as click, fill, read text, and dynamic element selection.

| `scenarios/`
| Business-flow layer. Scenario classes combine DAO methods and perform functional assertions.

| `tests/`
| Thin Pytest tests. Tests call scenario methods and provide markers such as `sanity` and `testrail`.

| `reports/`
| Runtime output folder for logs, Allure raw results, generated Allure HTML reports, and screenshots/attachments where applicable.
|===

=== `conftest.py` Execution Control

`conftest.py` wires the complete deterministic framework together.

It adds custom Pytest options:

[source,text]
----
--env        qa / uat / prod
--testrail   true / false
--report     true / false
----

It also uses pytest-playwright options such as:

[source,text]
----
--browser chromium
--headed
----

The main Pytest lifecycle implemented in this repository is:

[source,text]
----
pytest_configure
  ↓
sets Allure raw result path when --report=true

pytest_sessionstart
  ↓
prepares allure-results when --report=true

configAgent fixture
  ↓
loads environment config and runtime command values

browserInstance fixture
  ↓
launches Chromium / Firefox / WebKit once per session

isolatedBrowserContext fixture
  ↓
creates a fresh isolated context per test

browserPage fixture
  ↓
creates a new page, opens base URL, attaches page to request.node

runtimeAgent fixture
  ↓
creates RuntimeAgent for each test

pytest_runtest_makereport
  ↓
captures test outcome, attaches failure screenshots, captures TestRail results

pytest_sessionfinish
  ↓
generates final Allure HTML report and optionally publishes TestRail results
----

=== Configuration Layer

The configuration layer is stored under `config/`.

[source,text]
----
config/
├── global_config.py
├── qa_config.py
├── uat_config.py
└── prod_config.py
----

`global_config.py` contains shared execution settings:

[source,python]
----
GLOBAL_CONFIG = {
    "slow_mo": 0,
    "playwright_timeout": 30000,
    "viewport": {
        "width": 1366,
        "height": 768,
    },
    "locale": "en-AU",
    "timezone_id": "Australia/Melbourne",
    "video": "retain-on-failure",
    "tracing": "retain-on-failure",
    "screenshot": "only-on-failure",
    "ignore_https_errors": True,
    "accept_downloads": True,
}
----

Environment-specific files provide the base URL and credentials:

[source,python]
----
QA_CONFIG = {
    "base_url": "https://tutorialsninja.com/demo/index.php?route=common/home",
    "adminCredentials": {
        "valid_email": "qa_user@example.com",
        "valid_password": "123456",
    },
}
----

`ConfigAgent` combines:

[source,text]
----
GLOBAL_CONFIG
  + selected environment config
  + runtime command-line values
----

Example access pattern:

[source,python]
----
self.runtimeAgent.get_config_value("base_url")
self.runtimeAgent.get_config_value("adminCredentials.valid_email")
self.runtimeAgent.get_config_value("playwright_timeout")
----

==== `RuntimeAgent`

`coreAgents/runtimeAgent.py` is the main test-facing object.

Each Pytest test receives this fixture:

[source,python]
----
def test_userLogin(runtimeAgent):
    LoginScenarios(runtimeAgent).verify_successful_login()
----

`RuntimeAgent` currently holds:

[source,text]
----
Playwright page
ConfigAgent
ActionAgent
HomePageDAO
LoginPageDAO
MyAccountPageDAO
RegisterPageDAO
ProductPageDAO
----

This design lets scenario classes access all page DAOs through one runtime object:

[source,python]
----
self.runtimeAgent.homePageDao.navigate_to_login_page()
self.runtimeAgent.loginPageDao.enterUserEmailAndPassword()
self.runtimeAgent.myAccountPageDao.getMyAccountText()
----

==== `ActionAgent`

`coreAgents/actionAgent.py` is the reusable Playwright action wrapper.

Current action methods include:

[source,text]
----
click(target, description="")
fill(target, value, description="")
get_text(target, description="")
is_visible(target, timeout=5000, description="")
wait_for_url_contains(partial_url)
wait_for_page_load()
take_screenshot(screenshot_name)
----

It accepts either:

[source,text]
----
Playwright Locator object
selector string
----

Example usage from DAO:

[source,python]
----
self.click(self.homePageLocators.myAccountDropdownHomepage)
self.fill(self.loginPageLocators.userEmail, "user@example.com")
----

==== `AllureAgent`

`coreAgents/allureAgent.py` centralizes Allure reporting.

Responsibilities:

[source,text]
----
prepare_allure_results()
write_environment_file(config_agent)
write_executor_file()
attach_screenshot(page, screenshot_name)
attach_failure_screenshot(page, test_name)
generate_html_report()
cleanup_old_reports()
----

Allure flow:

[source,text]
----
--report=true
  ↓
pytest_configure sets allure result path
  ↓
pytest_sessionstart cleans/creates reports/allure-results
  ↓
Tests execute and Allure raw JSON is created
  ↓
Failure screenshot is attached directly to Allure
  ↓
pytest_sessionfinish generates HTML report
  ↓
reports/allure-reports/allure_report_YYYYMMDD_HHMMSS/
----

The current implementation keeps the latest 5 generated Allure report folders.

==== `TestRailAgent`

`coreAgents/testrailAgent.py` optionally publishes test results to TestRail.

It works with test markers:

[source,python]
----
@pytest.mark.testrail(case_id='C46')
@pytest.mark.sanity
def test_userLogin(runtimeAgent):
    LoginScenarios(runtimeAgent).verify_successful_login()
----

TestRail flow:

[source,text]
----
pytest_runtest_makereport
  ↓
capture result and TestRail case ID
  ↓
pytest_sessionfinish
  ↓
create one TestRail run
  ↓
publish each captured result using add_result_for_case
----

Status mapping:

[cols="1,1", options="header"]
|===
| Pytest outcome | TestRail status

| passed
| 1 / Passed

| skipped
| 2 / Blocked

| failed
| 5 / Failed
|===

[CAUTION]
====
The uploaded code contains TestRail defaults in `testrailAgent.py`. For a production-quality repository, do not hardcode TestRail usernames or API keys. Use environment variables or Jenkins credentials instead, and rotate any API key that may have been committed.
====

=== Page Object Locator Layer

Locator classes are stored under `pageObjectLocators/`.

[source,text]
----
pageObjectLocators/
├── homePageLocators.py
├── loginPageLocators.py
├── myAccountPageLocators.py
├── productPageLocators.py
└── registerPageLocators.py
----

These classes store Playwright locator objects only.

Example style from the repository:

[source,python]
----
self.myAccountDropdownHomepage = self.page.locator("//span[text()='My Account']")
self.loginButtonHomepage = self.page.locator("//a[text()='Login']")
self.userEmail = self.page.locator("//input[@name='email']")
self.searchBar = self.page.locator("//input[@name='search']")
----

Locator layer rule:

[source,text]
----
Locators only.
No actions.
No assertions.
No business flow.
----

=== DAO Layer

DAO classes are stored under `dao/`.

[source,text]
----
dao/
├── homePageDao.py
├── loginPageDao.py
├── myAccountPageDao.py
├── productPageDao.py
└── registerPageDao.py
----

DAO classes extend `ActionAgent` and perform page-level actions.

Example pattern:

[source,python]
----
class HomePageDAO(ActionAgent):
    def __init__(self, runtimeAgent):
        super().__init__(runtimeAgent)
        self.homePageLocators = HomePage(runtimeAgent)

    def clickOnMyAccountDropdown(self):
        self.click(self.homePageLocators.myAccountDropdownHomepage)
----

DAO layer rule:

[source,text]
----
DAO = page-level actions and small page-level reads.
Scenario = business workflow and assertions.
Test = thin call into scenario.
----

=== Test Layer

Tests are stored under `tests/`.

[source,text]
----
tests/
├── test_LoginFunctionality.py
├── test_LogoutFunctionality.py
├── test_productCompareFunctionality.py
├── test_registrationUser.py
└── test_searchFunctionality.py
----

Tests are intentionally thin.

Example:

[source,python]
----
@pytest.mark.testrail(case_id='C46')
@pytest.mark.sanity
def test_userLogin(runtimeAgent):
    LoginScenarios(runtimeAgent).verify_successful_login()
----

Test layer rule:

[source,text]
----
Tests should not directly use page locators.
Tests should not directly use Playwright page actions.
Tests should call scenario methods.
----

== AI Assist Layer

The AI assist layer is optional and separate from the deterministic framework.

It is stored mainly in:

[source,text]
----
aiAgents/
aiInputs/
aiOutputs/
----

The uploaded repository currently contains a recording-driven AI workflow:

[source,text]
----
Playwright Codegen Recording
  ↓
RecordingAgent
  ↓
aiInputs/recordings/<run>_recording.py
aiInputs/runs/<run>.json
  ↓
recordedCodePlannerAgent.md
  ↓
aiOutputs/plans/<run>_plan.md
  ↓
recordedCodeGeneratorAgent.md
  ↓
aiOutputs/recommendations/<run>_recommendations.md
  ↓
Human review
  ↓
Manual update to deterministic framework files
----

[IMPORTANT]
====
The AI layer does not automatically overwrite framework files. The generated recommendations are a handoff for human review.
====

=== AI Layer Files

[cols="1,2", options="header"]
|===
| File / Folder | Purpose

| `aiAgents/recording_agent.py`
| Python helper class that launches Playwright Codegen, saves a recording file, and creates a run manifest.

| `aiAgents/scripts/record_flow.py`
| CLI script used to record a browser flow.

| `aiInputs/recordings/`
| Stores raw Playwright Codegen recordings.

| `aiInputs/runs/`
| Stores JSON run manifests that connect recordings, planner prompts, generator prompts, and output paths.

| `aiInputs/prompts/recordedCodePlannerAgent.md`
| Planner prompt. Converts a raw recording into an implementation-ready test plan.

| `aiInputs/prompts/recordedCodeGeneratorAgent.md`
| Generator prompt. Converts an approved plan into locator, DAO, scenario, and test recommendations.

| `aiOutputs/plans/`
| Stores planner outputs.

| `aiOutputs/recommendations/`
| Stores generator outputs / code recommendations.
|===

=== RecordingAgent Flow

`RecordingAgent` builds and runs a Playwright Codegen command similar to:

[source,text]
----

  --target python-pytest \
  --browser chromium \
  --output aiInputs/recordings/<run>_recording.py \

----

The user records a real browser journey, closes Codegen, and the agent creates:

[source,text]

  ↓

python -m venv .venv

== How To Run Tests

Run sanity tests in headed mode:

[source,powershell]
----
python -m pytest -m sanity --env=qa --browser chromium --headed --report=true --testrail=false -s
----

Run sanity tests in headless mode:

[source,powershell]
----
python -m pytest -m sanity --env=qa --browser chromium --report=true --testrail=false -s
----

Run all tests without Allure HTML generation:

[source,powershell]
----
python -m pytest --env=qa --browser chromium --report=false --testrail=false -s
----

Run with TestRail publishing:

[source,powershell]
----
$env:TESTRAIL_BASE_URL="https://your-instance.testrail.io"
$env:TESTRAIL_USERNAME="your_email@example.com"
$env:TESTRAIL_API_KEY="your_api_key"
$env:TESTRAIL_PROJECT_ID="2"

python -m pytest -m sanity --env=qa --browser chromium --report=true --testrail=true -s
----

== Recommended Framework Naming Improvements

The current framework works with these names, but the following naming improvements would make it more consistent:

[cols="1,2", options="header"]
|===
| Current style | Suggested style

| `homePageDao.py`
| `homePageDAO.py` or keep one convention consistently.

| `LoginPage`, `HomePage`, `ProductPage`
| `LoginPageLocators`, `HomePageLocators`, `ProductPageLocators` for clearer purpose.

| `enterUserEmailAndPassword()`
| Split into `enterEmail()` and `enterPassword()` for reusable negative testing.

| Hardcoded user data inside DAO
| Move reusable credentials to config and test-specific data to test data files.
|===

== Final Architecture Summary

[source,text]
----
AI Assist Layer
  ├── records real flow using Playwright Codegen
  ├── generates test plan through planner prompt
  ├── generates code recommendations through generator prompt
  └── requires human review before framework update

Deterministic Framework Layer
  ├── executes tests through Pytest
  ├── manages browser/page/context through conftest.py
  ├── exposes RuntimeAgent to tests
  ├── runs Scenario → DAO → ActionAgent → Locator → Playwright
  ├── creates Allure reports
  └── optionally publishes TestRail results
----

The framework is strongest when the layers remain separated:

[source,text]
----
AI suggests.
Human reviews.
Deterministic framework executes.
CI/CD remains stable.
----
